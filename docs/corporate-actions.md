# 市場情緒 20 日動能的除權息查核

目前行情是未還原收盤價。20 日動能在所需的 20 個相鄰交易日均經 TWSE 除權息、減資恢復買賣及面額變更三份報表查核後，以官方的除權息參考價調整基準日收盤價：每次可支援的除權息事件乘上 `除權息參考價 / 除權息前收盤價`，再與當日收盤價比較。必須核對官方「除權息前收盤價」與行情的前一交易日收盤價；減資、面額變更、價格不一致、任一天未查核或行情缺漏時，該股動能維持缺值。這是價格序列的還原口徑，不宣稱是含現金股利再投資的總報酬，也不把缺值當作 50 分。

最新一天需要 21 筆連續行情；20 點每日情緒趨勢最早一天也要往前 20 日，所以初次只查核最近 40 個市場交易日。目前正式市場資料至 2026-10-22，對應 2026-08-25 至 2026-10-22。TWSE TWT49U 區間報表有 182 筆數字代號除權息事件，TWTAUU 有 9 筆減資事件，TWTB8U 有 1 筆面額變更事件；另存 40 筆已查核日期。歷史日期若早於這個窗口，動能維持缺值，直到按該日期的 20 日窗口補查。

新增資料存在既有 `stockapps-t86` D1：`corporate_action_events` 只存事件，`corporate_action_coverage` 區分「三份報表均已查核」與「尚未查核」，`corporate_action_meta` 的單列修訂值用於清除市場 Summary 的 Durable Object 舊快取。沒有逐股外部請求，也沒有新增 KV 寫入。每日同步只在既有市場發布完成、台北時間 20:30 以後依次請求三份報表；來源失敗或任何一份回報無事件時至少間隔 30 分鐘再確認一次。D1 狀態保證最多兩輪、六次外部請求。

部署順序：

1. 先套用 `cloudflare/migrations/0004_corporate_actions.sql`，並確認三張表存在。
2. 執行 `node scripts/prepare-corporate-actions-backfill.js --output=.wrangler/corporate-actions-backfill.sql`。腳本只讀正式市場日曆與 TWSE 區間報表，產生 SQL，**不會寫入遠端 D1**。核對輸出的 `tradingDays`、`events`、SQL 檔與來源日期。
3. 將 SQL 匯入既有 D1，查詢事件、查核日及修訂列數；再部署 Worker。正式環境啟用前，先檢查當日 D1 Rows Read/Written 剩餘額度，以及 Worker Cron CPU 和錯誤率。若 10 ms Free CPU 限制無法滿足，保持功能未啟用，不提高排程或寫入頻率。
4. 部署後核對最新 Summary 的動能有效樣本、歷史日期沒有引用未來事件，以及次日排程的外部請求與 D1 寫入次數。

2026-10-24 讀取的專案 D1 狀態：22,396,928 bytes；近 24 小時讀取 5,777 列、寫入 23 列。192 事件、40 查核日與修訂列在本機 SQLite 匯入後，檔案增加 20,480 bytes；雲端 D1 以 Metrics 為準。Free 方案的單庫 500 MB、每日讀取 5,000,000 列、寫入 100,000 列、每次 Cron 10 ms CPU 與 50 次外部子請求上限均以部署當日官方規格和觀測值重新核對。

三份 TWSE 報表仍不能代表所有可能的公司行動；未支援事件只標記、不中途猜算。若窗口內出現無法解釋的價格跳變或未查核來源，應停止該股動能計算並查明來源，不應自動把它當作市場方向。
