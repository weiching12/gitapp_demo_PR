# 株研程式審視與修正（2026-10-25）

檢查基準：`feat/stock-insight-dashboard`，commit `00c1913930cd6cb412b08fe4bad7b7f9684df4f8`。

本次檢查前端市場清單、自選、產業、評分與圖表互動、API／共用規則、快取、公司行動、造訪統計、同步與測試入口。評分維持實際程式的 V1.2；不套回舊需求稿的 V1.1 分數上限，不調整權重或投資策略。

## 已修正

| 問題 | 修正 |
| --- | --- |
| HEAD 先發起市場摘要計算時，並行 GET 可能收到空回應 | 共用工作一律保存含本文回應，僅在個別 HEAD 回傳時去除本文 |
| 快速切換到已有快取日期，舊網路請求的載入狀態未清除 | 每次選擇獨立更新載入狀態；過時請求的成功／失敗皆不改動目前選擇 |
| 日期／KD 設定請求失敗可能回到尚未完成載入的前一次選擇 | 以最近成功摘要回復日期／設定，重新呈現一致資料 |
| 評分請求延遲完成，可能覆蓋之後開啟的設定或說明視窗 | 驗證視窗開啟序號、股票及完整日期／設定鍵；評分比對使用發起時的摘要 |
| 法人明細與評分使用相同 Analysis API 卻維護兩份快取 | 合併為一份完整個股詳情快取，已取得的明細可跨入口重用 |
| 自選摘要失敗後沒有重試入口，過時失敗可能污染新日期 | 新增重新載入自選按鈕；錯誤只更新對應的目前日期／設定 |
| 法人買株頁隱藏日期選單，但 API 使用前一頁歷史日期，示範模式則使用最新日期 | 對齊既有「最新完整交易日」設計，正式／示範模式均使用最新資料；詳情日期取自實際資料 |
| KD 技術建議可能將缺漏前一市場交易日的資料視為連續兩日 | 已知市場日曆時必須有緊接的前一交易日，否則顯示資料不足；不改 KD 遞迴公式 |
| 公司行動僅接受數字代號，漏掉行情已支援的英文尾碼 ETF | 沿用共用 validSymbol；調整相關測試 |
| 來源更正刪除公司行動事件後，Upsert 留下舊事件 | 在同一交易內取代指定查核日期的事件、狀態及修訂值；失敗整批回滾 |
| 今日造訪功能已取代舊在線人數，但 runtime 測試仍斷言 90 秒 TTL | 測試與文件改為現行台北每日造訪契約；前端跨日後重新登記造訪 |
| 舊測試替代 provider 缺少 main.js 所需的 loadMarketSummary 匯出 | 補足示範測試介面，誤用 API 時明確失敗 |
| 未使用的匯入及重複計算 | 移除 main.js 的 8 個未使用指標匯入；RVOL20 沿用 getSnapshot 計算，明確傳入市場日曆 |

市場摘要快取 schema 一併更新，避免部署後繼續使用舊的衍生判讀結果。瀏覽器測試伺服器固定監聽 127.0.0.1，以符合測試 URL 並避免不必要的網路介面列舉。
